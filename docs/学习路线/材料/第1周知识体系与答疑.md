## 知识体系总图

```text
文字
  → Tokenizer（tokenize / encode / __call__）
  → input_ids + attention_mask
  → Embedding 层（查表成向量）
  → Decoder（层间仍是向量）
  → logits
        ├─ 推理：选 token → 循环 → decode 成字
        └─ 训练：Loss → backward（写梯度）→ optimizer.step（改权重）
```

四层不要混：

| 层 | 解决什么 | 不是什么 |
|---|---|---|
| Tokenizer | 文字 ↔ 编号 | 不是 Transformer Encoder |
| Embedding | 编号 → 向量（模型内部一层） | 不是 BGE 那种检索模型 |
| 训练一步 | 让预测靠近标签 | `model.train()` 本身不是开始训练 |
| 大厂工程 / 评测 | 规模、容错、门禁 | 不是另一套反向传播公式 |

## 1. Tokenizer：切分与编号

### 1.1 四个 API

```text
原文
  ├─ tokenize                  → 文字碎片
  │       └─ convert_tokens_to_ids → id 列表（只查表，不会切句）
  ├─ encode                    → id 列表（切 + 查，可加特殊符）
  └─ tokenizer(...) 即 __call__ → 字典：input_ids + attention_mask（可变成张量）
```

不加特殊符号时，本仓库 SmolLM2 上通常：

```text
tokenize + convert_tokens_to_ids
    ≈ encode(..., add_special_tokens=False)
    ≈ tokenizer(text)["input_ids"] 里的数字
```

`tokenizer` 是对象不是函数；`tokenizer(...)` 调用的是 `__call__`。  
`model(**inputs)` 的 `**` 表示按名字把字典拆成关键字参数（见 `learn/py/call.py`）。

### 1.2 `input_ids` 与 `attention_mask`

| 字段 | 含义 |
|---|---|
| `input_ids` | 每个位置的词表编号，拿去 Embedding 查向量 |
| `attention_mask` | 与 ids 等长；`1`=真实 token，`0`=padding，注意力应忽略 |

单句无补齐时 mask 全是 1。短句和长句一起 padding 时才关键。本模型 pad 常与 eos 同为 id=2。

### 1.3 通用 BPE，不是「一个汉字一个 id」

- 词表约 49152，预训练定死；不是汉字字典，也不是 Java 字典。
- **BPE**：从很小的片（本模型是 UTF-8 字节）起，合并高频相邻对。
- 英文常见词常 1 个 token；中文常被拆成多片，显示可能像乱码，`decode` 后仍是正确中文。
- `Ġ` 多表示前面有空格。

其它切法（光谱）：整词 → 子词（BPE / WordPiece / Unigram）→ 单字 → 纯字节。  
SentencePiece 是实现，不是第四种算法。

### 1.4 字不在整词表里怎么办

Byte-level BPE 会拆成字节/子词再编码，一般**不会**变成 UNK。  
「不在表里」≠ 模型看不见；看不见的是整词 id，看得见的是组成它的小片。  
理解上：常见组合见得多就稳，生僻字能编码但可能弱一些。微调通常不为此改词表。

## 2. Embedding：数字如何变成向量

路径：

```text
Tokenizer（模型外）→ input_ids
  → Embedding 层（模型最前，get_input_embeddings()）→ 向量
  → Decoder 各层 → 向量
  → lm_head → logits
```

- `get_input_embeddings()` 拿到的是 `nn.Embedding` 查表，本仓库即 `model.model.embed_tokens`，权重约 `[49152, 576]`。
- `vectors = embedding(ids)`：用 id 当行号取 `weight[id]`，形状从 `[batch, seq]` 变成 `[batch, seq, 576]`。
- 验证：`vectors[0,0]` 应与 `weight[token_id]` 几乎相等（`torch.allclose`）。
- 这与独立句向量模型（BGE / E5）不是一回事。
- SmolLM2 常 `tie_word_embeddings=True`：输入表与 `lm_head` 共用权重。

三种输出：层间向量 ≠ logits ≠ `tokenizer.decode` 得到的汉字。

## 3. 训练一步：开关、Dropout、反传、更新

### 3.1 谁才是「开始训练」

```text
model.train()          只切换模式（换挡），不改权重
optimizer.zero_grad()  清旧梯度
model(...)             Forward，得到 loss
loss.backward()        写 param.grad（阅卷）
optimizer.step()       按梯度改权重（改作业）
```

`model.eval()` 切推理行为。`07`/`08` 用 eval；`09` 用 train。  
`scripts/sft001.py` 的 `trainer.train()` 才是多步循环；每一步仍是上面这条油门。

`train()` **不会**改变：权重数值、`requires_grad`、有没有 `no_grad`。  
能反传看图和 `requires_grad`；能改权重看 `step()`。

### 3.2 `train()` 具体改哪些行为

给子模块打上 `training=True`，各层 `forward` 自己换算法：

| 层 | train() | eval() | 本仓库 SmolLM2 |
|---|---|---|---|
| Dropout | 随机置 0，留下的放大 | 原样输出 | `attention_dropout=0`，几乎无差别 |
| BatchNorm | 用当前 batch 统计并更新 running 均值 | 用记住的均值 | 本模型是 RMSNorm，一般不看该标志 |
| 注意力 dropout | 随机打掉部分注意力 | 完整注意力 | 概率为 0 |

习惯上仍成对使用 train/eval，换到带 Dropout 的模型才看出差别。

### 3.3 Dropout 小例子与常见误解

训练随机蒙一部分神经元（下标，不是「句子第 2、3 个字」），每次蒙的位置可不同。  
推理 **eval 关闭 Dropout**，用全部神经元，不沿用某一次训练的蒙眼位置。

inverted dropout：训练时留下的乘 `1/(1-p)`，使期望接近推理全开。  
若推理还 `train()`，每次随机蒙眼，预测会乱跳。数字示例：`python learn/py/dropout.py`。

### 3.4 `backward` 与 `step`

| | `loss.backward()` | `optimizer.step()` |
|---|---|---|
| 做什么 | 链式法则算梯度，写入 `.grad`（会累加） | SGD：`weight ← weight - lr × grad` |
| 不做什么 | 不改权重、不生成文本 | 不算新梯度，默认不清 `.grad` |

只有 backward：权重不动。只有 step：`.grad` 为空或是旧的。  
两次 backward 不 `zero_grad`：梯度累加。  
`no_grad` 下没有计算图，不能 backward。

## 4. 和互联网大厂训练：公式相同，外壳不同

**本质相同：** 预测下一个 token + 交叉熵 + 反传 + 优化器。不是另一套物理学。

**差在知识链位置与量级：**

```text
大厂：万亿 token 预训练 → Base → SFT → 偏好对齐 → 安全/产品
你们：现成 SmolLM2-135M → 小数据 Java SFT（09 甚至只 1 步、只动 Embedding）
```

| | 当前脚本 | 大厂日常多出来的壳 |
|---|---|---|
| 时间 | 一步或数 epoch | 连续数天 + 断点续训 |
| 数据 | 干净短 jsonl | 数据工厂 + 跳坏 batch |
| 算力 | CPU、bs=1、LoRA | 千卡并行、混合精度 |
| 监控 | 看 loss 变小 | 尖刺、裁剪、NaN 回退 |
| 评测 | 十几条 test + NLL/F1 | 多基准 + 人工 + 安全 + A/B |

大厂如何处理常见问题（思路，不是某一家内部机密）：

- **不断点：** checkpoint（权重+优化器+数据位置）、弹性补卡、超时踢故障节点。  
- **脏数据 / loss 尖刺：** 预训练前清洗配比；训练中跳过 NaN/极大 loss；梯度裁剪；warmup。  
- **卡死：** 多为分布式通信等死，超时重启。  
- **数值：** 多用 BF16；FP16 配 loss scaling；Inf 则跳过或回退 checkpoint。  
- **分布式：** DDP / ZeRO-FSDP / 张量并行 / 流水线；逻辑上仍是一次 backward + 一次 step。  
- **吞吐：** Flash Attention、packing、梯度累积、数据加载别让 GPU 空等。

入职「应用微调」吃当前这条路；万卡预训练还要分布式、容错、数据工程。地基是同一套公式，缺的是规模和项目，不是魔法。

## 5. 训完如何评质量：没有一张统考卷

**没有**「MMLU 达到 xx 即可上线」的国际强制标准。行业习惯是 **可复现的多层评测**，不是一个万能分数。

```text
1. 训练健康     loss 是否正常（没训崩 ≠ 质量好）
2. 能力基准     公开题 + 内部私有集（防污染、防刷榜）
3. 人工         绝对分或 A vs B 成对比较
4. 安全         拒答、越狱、违法；过不了不能发版
5. 产品         延迟、成本、好评、A/B
```

公开基准只是事实标准（MMLU、GSM8K、HumanEval、IFEval、C-Eval、MT-Bench 等），必须固定解码参数。  
NLL/PPL 适合监控和同系列对比；字面 F1 适合小数据领域 SFT，开放聊天很弱。  
选择题高 ≠ 对话好用；数据污染会让公开分虚高。

你们已有最小闭环：独立 `test.jsonl` + 参考答案 + NLL/字面重合。往厂里习惯靠：评测脚本固定、题不与训练重复、开放生成加少量人工。

### 5.1 本仓库三个数字：行业地位 + 手算

| 名称 | 是不是行业常用 | 本仓库怎么算 |
|---|---|---|
| Reference | 不是分数，是标准答案（gold） | `test.jsonl` 的 `completion` |
| Token F1 | **F1 公式常用**；本实现是简化「字符集合」 | `set(pred)` 与 `set(ref)` 的 P/R 调和平均 |
| Keyword Hit | **不是标准名称** | 英文词 + 中文二字片，看预测覆盖率 |
| NLL | **是**，常同时报 PPL=`exp(NLL)` | 参考答案的平均 `-ln P`；正式脚本只对 assistant 计 |

行业亲戚：Exact Match、BLEU、ROUGE-L、BERTScore、Pass@k、人工 A/B、延迟（`eval_compare.py` 已记 Latency）。

**Token F1 手算**（`11_eval_metrics.py` 会打印）：

```text
ref  = 不能实例化      → {不,能,实,例,化}     大小 5
pred = 不能直接实例化  → {不,能,直,接,实,例,化} 大小 7
交集 = {不,能,实,例,化} 大小 5
P=5/7≈0.714  R=5/5=1  F1=2PR/(P+R)≈0.833
```

顺序和字频都丢掉了：「实例化不能」分数相同。SQuAD 的 token F1 会按词计数，比这更严。

**Keyword Hit 手算**：

```text
ref  = interface 不能实例化
关键词 = interface, 不能, 能实, 实例, 例化
pred = 接口不能被实例化
命中 不能 / 实例 / 例化，未命中 interface / 能实
Hit = 3/5 = 0.600
```

**NLL 手算**（3 个 token 概率 0.50 / 0.40 / 0.20）：

```text
-ln P = 0.693, 0.916, 1.609
平均 NLL ≈ 1.073    PPL = exp(NLL) ≈ 2.92
```

数字越小越「不意外」。`11` 脚本整段算 loss 是演示；`eval_compare.completion_nll` 套 chat 且只对答案计。

跑：`python learn/week01/11_eval_metrics.py`

### 7.2 Day 1：`01`～`05` Tokenizer

**`01_load_tokenizer.py`**

```text
tokenizer, model_dir = load_tokenizer()
len(tokenizer) / tokenizer.vocab_size     # 约 49152
bos / eos / pad / unk 的符号和 id
```

从 `tokenizer.json` 等文件加载。结论：模型只认识 `0 ~ vocab_size-1`；词表预训练定死，本项目微调一般不改。

**`02_token_and_id.py`**

```text
tokens = tokenizer.tokenize(text)
ids    = tokenizer.convert_tokens_to_ids(tokens)
tokenizer.decode([tid])   # 单个 id 还原成可读碎片
```

可命令行换句子。`Ġ` 打印时换成 `▁`，表示前面常有空格。结论：计算用的是数字，同一词表下同一片段 id 固定。

**`03_encode_decode.py`**

```text
ids_plain   = tokenizer.encode(text, add_special_tokens=False)
ids_special = tokenizer.encode(text, add_special_tokens=True)
tokenizer.decode(ids, skip_special_tokens=True)
```

本 tokenizer 对普通句子常常不加 bos/eos；对话符号主要靠 `chat_template`（见 `10`）。结论：`tokenizer.encode` ≠ Transformer Encoder。

**`04_chinese_vs_english.py`**

三句英文、三句中文对照：`tokenize` 看碎片，`convert_tokens_to_ids` 看数字，`decode` 拼回去。英文高频词常 1 个 token；中文常多片、显示像乱码。结论：Byte-level BPE，不是「一个汉字一个 id」，也不是 Java 字典。

**`05_special_tokens.py`**

```text
tokenizer.convert_tokens_to_ids("<|im_start|>")  # 等
vocab = tokenizer.get_vocab()                    # 字符串 → id
"Java" in vocab    vs   tokenizer.tokenize("什么")
```

Instruct 靠 `<|im_start|>` / `<|im_end|>` 标角色。词表没有整词就拆，不会直接报错。

### 7.4 Day 3：`07` 前向、`08` Embedding、`call.py`

**`learn/py/call.py`**（不加载模型，先搞懂星号）

| 写法 | 意思 |
|---|---|
| 定义 `*args` / `**kwargs` | 打包：多出来的位置参数进元组，关键字进字典 |
| 调用 `*列表` / `**字典` | 拆包：`f(*[1,2])` = `f(1,2)`；`f(**{"x":1})` = `f(x=1)` |
| 对象 `obj(...)` | 走 `__call__` |

对照 `07`：`tokenizer(text)` 是 `__call__`；`model(**inputs)` 把 `input_ids`、`attention_mask` 按名字传入。

**`07_forward_logits.py`**

```text
model.eval()
inputs = tokenizer(text, return_tensors="pt")   # BatchEncoding：ids + mask
with torch.no_grad():
    logits = model(**inputs).logits             # [1, seq, vocab]
next_id = argmax(logits[0, -1])                 # 只预测下一个碎片
model.generate(..., max_new_tokens=12)          # 循环前向才得到一段话
apply_chat_template(...)                        # 套对话格式再生成
```

裸问题容易乱续写；套 chat 后才像答题。结论：logits 是分数；一次前向 ≠ 完整答案。

**`08_embedding.py`**

```text
ids = tokenizer.encode("Java", add_special_tokens=False, return_tensors="pt")
embedding = model.get_input_embeddings()        # nn.Embedding = embed_tokens
vectors = embedding(ids)                        # [1, seq, 576]
allclose(vectors[0,0], embedding.weight[token_id])  # 查表层 = 按行取表
lm_head 与 embedding 常 tie_word_embeddings（共用权重）
```

结论：没有独立 Encoder，也会 Embedding 成向量；这不是 BGE 那种句向量模型。

### 7.5 Day 4：`09` 训练一步、`dropout.py`

**`learn/py/dropout.py`**

```text
x = [1, 2, 3, 4, 5]
drop = nn.Dropout(p=0.5)
drop.train() → 每次随机置 0，留下的 × 2（inverted dropout）
drop.eval()  → 原样输出，两次相同
```

蒙的是向量**下标**，不是「句子第 2、3 个字」。推理继续 `train()` 会乱跳。SmolLM2 的 `attention_dropout=0`，大模型上几乎看不出差别，所以用这个小例子。

**`09_loss_backward.py`**

```text
冻住全部参数，只解冻 Embedding
labels = input_ids.clone()          # 因果 LM：用位置 i 预测 i+1
model.train()
optimizer.zero_grad()
loss = model(input_ids=..., labels=...).loss
loss.backward()                     # 只写 .grad
optimizer.step()                    # SGD：weight ← weight - lr × grad
打印某个权重 before / after
```

`scripts/sft001.py` 的 `trainer.train()` 才是多步循环；每一步仍是这条油门。正式训练多用 AdamW + LoRA，公式同类。

### 7.6 Day 5：`10_sft_messages.py`

```text
{prompt, completion}
  → [{system}, {user: prompt}, {assistant: completion}]   # 与 sft001.to_messages 一致
apply_chat_template(..., add_generation_prompt=False)     # 训练：含答案
```

观察 `<|im_start|>role` … `<|im_end|>`。结论：Base 会续写；问答 SFT 用 Instruct + 对话模板。
