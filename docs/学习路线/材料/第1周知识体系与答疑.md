---

## 知识体系总图

```text
文字
  → Tokenizer（tokenize / encode / __call__）
  → input_ids + attention_mask
  → Embedding 层（查表成向量）
  → Decoder（层间仍是向量）
  → logits
        ├─ 推理：选 token → 循环 → decode 成字
        └─ 训练：Loss → backward（写梯度）→ optimizer.step（改权重）
```

四层不要混：

| 层 | 解决什么 | 不是什么 |
|---|---|---|
| Tokenizer | 文字 ↔ 编号 | 不是 Transformer Encoder |
| Embedding | 编号 → 向量（模型内部一层） | 不是 BGE 那种检索模型 |
| 训练一步 | 让预测靠近标签 | `model.train()` 本身不是开始训练 |
| 大厂工程 / 评测 | 规模、容错、门禁 | 不是另一套反向传播公式 |

## 1. Tokenizer：切分与编号

### 1.1 四个 API

```text
原文
  ├─ tokenize                  → 文字碎片
  │       └─ convert_tokens_to_ids → id 列表（只查表，不会切句）
  ├─ encode                    → id 列表（切 + 查，可加特殊符）
  └─ tokenizer(...) 即 __call__ → 字典：input_ids + attention_mask（可变成张量）
```

不加特殊符号时，本仓库 SmolLM2 上通常：

```text
tokenize + convert_tokens_to_ids
    ≈ encode(..., add_special_tokens=False)
    ≈ tokenizer(text)["input_ids"] 里的数字
```

`tokenizer` 是对象不是函数；`tokenizer(...)` 调用的是 `__call__`。  
`model(**inputs)` 的 `**` 表示按名字把字典拆成关键字参数（见 `learn/py/call.py`）。

### 1.2 `input_ids` 与 `attention_mask`

| 字段 | 含义 |
|---|---|
| `input_ids` | 每个位置的词表编号，拿去 Embedding 查向量 |
| `attention_mask` | 与 ids 等长；`1`=真实 token，`0`=padding，注意力应忽略 |

单句无补齐时 mask 全是 1。短句和长句一起 padding 时才关键。本模型 pad 常与 eos 同为 id=2。

### 1.3 通用 BPE，不是「一个汉字一个 id」

- 词表约 49152，预训练定死；不是汉字字典，也不是 Java 字典。
- **BPE**：从很小的片（本模型是 UTF-8 字节）起，合并高频相邻对。
- 英文常见词常 1 个 token；中文常被拆成多片，显示可能像乱码，`decode` 后仍是正确中文。
- `Ġ` 多表示前面有空格。

其它切法（光谱）：整词 → 子词（BPE / WordPiece / Unigram）→ 单字 → 纯字节。  
SentencePiece 是实现，不是第四种算法。

### 1.4 字不在整词表里怎么办

Byte-level BPE 会拆成字节/子词再编码，一般**不会**变成 UNK。  
「不在表里」≠ 模型看不见；看不见的是整词 id，看得见的是组成它的小片。  
理解上：常见组合见得多就稳，生僻字能编码但可能弱一些。微调通常不为此改词表。

## 2. Embedding：数字如何变成向量

路径：

```text
Tokenizer（模型外）→ input_ids
  → Embedding 层（模型最前，get_input_embeddings()）→ 向量
  → Decoder 各层 → 向量
  → lm_head → logits
```

- `get_input_embeddings()` 拿到的是 `nn.Embedding` 查表，本仓库即 `model.model.embed_tokens`，权重约 `[49152, 576]`。
- `vectors = embedding(ids)`：用 id 当行号取 `weight[id]`，形状从 `[batch, seq]` 变成 `[batch, seq, 576]`。
- 验证：`vectors[0,0]` 应与 `weight[token_id]` 几乎相等（`torch.allclose`）。
- 这与独立句向量模型（BGE / E5）不是一回事。
- SmolLM2 常 `tie_word_embeddings=True`：输入表与 `lm_head` 共用权重。

三种输出：层间向量 ≠ logits ≠ `tokenizer.decode` 得到的汉字。

## 3. 训练一步：开关、Dropout、反传、更新

### 3.1 谁才是「开始训练」

```text
model.train()          只切换模式（换挡），不改权重
optimizer.zero_grad()  清旧梯度
model(...)             Forward，得到 loss
loss.backward()        写 param.grad（阅卷）
optimizer.step()       按梯度改权重（改作业）
```

`model.eval()` 切推理行为。`07`/`08` 用 eval；`09` 用 train。  
`scripts/sft001.py` 的 `trainer.train()` 才是多步循环；每一步仍是上面这条油门。

`train()` **不会**改变：权重数值、`requires_grad`、有没有 `no_grad`。  
能反传看图和 `requires_grad`；能改权重看 `step()`。

### 3.2 `train()` 具体改哪些行为

给子模块打上 `training=True`，各层 `forward` 自己换算法：

| 层 | train() | eval() | 本仓库 SmolLM2 |
|---|---|---|---|
| Dropout | 随机置 0，留下的放大 | 原样输出 | `attention_dropout=0`，几乎无差别 |
| BatchNorm | 用当前 batch 统计并更新 running 均值 | 用记住的均值 | 本模型是 RMSNorm，一般不看该标志 |
| 注意力 dropout | 随机打掉部分注意力 | 完整注意力 | 概率为 0 |

习惯上仍成对使用 train/eval，换到带 Dropout 的模型才看出差别。

### 3.3 Dropout 小例子与常见误解

训练随机蒙一部分神经元（下标，不是「句子第 2、3 个字」），每次蒙的位置可不同。  
推理 **eval 关闭 Dropout**，用全部神经元，不沿用某一次训练的蒙眼位置。

inverted dropout：训练时留下的乘 `1/(1-p)`，使期望接近推理全开。  
若推理还 `train()`，每次随机蒙眼，预测会乱跳。数字示例：`python learn/py/dropout.py`。

### 3.4 `backward` 与 `step`

| | `loss.backward()` | `optimizer.step()` |
|---|---|---|
| 做什么 | 链式法则算梯度，写入 `.grad`（会累加） | SGD：`weight ← weight - lr × grad` |
| 不做什么 | 不改权重、不生成文本 | 不算新梯度，默认不清 `.grad` |

只有 backward：权重不动。只有 step：`.grad` 为空或是旧的。  
两次 backward 不 `zero_grad`：梯度累加。  
`no_grad` 下没有计算图，不能 backward。

## 4. 和互联网大厂训练：公式相同，外壳不同

**本质相同：** 预测下一个 token + 交叉熵 + 反传 + 优化器。不是另一套物理学。

**差在知识链位置与量级：**

```text
大厂：万亿 token 预训练 → Base → SFT → 偏好对齐 → 安全/产品
你们：现成 SmolLM2-135M → 小数据 Java SFT（09 甚至只 1 步、只动 Embedding）
```

| | 当前脚本 | 大厂日常多出来的壳 |
|---|---|---|
| 时间 | 一步或数 epoch | 连续数天 + 断点续训 |
| 数据 | 干净短 jsonl | 数据工厂 + 跳坏 batch |
| 算力 | CPU、bs=1、LoRA | 千卡并行、混合精度 |
| 监控 | 看 loss 变小 | 尖刺、裁剪、NaN 回退 |
| 评测 | 十几条 test + NLL/F1 | 多基准 + 人工 + 安全 + A/B |

大厂如何处理常见问题（思路，不是某一家内部机密）：

- **不断点：** checkpoint（权重+优化器+数据位置）、弹性补卡、超时踢故障节点。  
- **脏数据 / loss 尖刺：** 预训练前清洗配比；训练中跳过 NaN/极大 loss；梯度裁剪；warmup。  
- **卡死：** 多为分布式通信等死，超时重启。  
- **数值：** 多用 BF16；FP16 配 loss scaling；Inf 则跳过或回退 checkpoint。  
- **分布式：** DDP / ZeRO-FSDP / 张量并行 / 流水线；逻辑上仍是一次 backward + 一次 step。  
- **吞吐：** Flash Attention、packing、梯度累积、数据加载别让 GPU 空等。

入职「应用微调」吃当前这条路；万卡预训练还要分布式、容错、数据工程。地基是同一套公式，缺的是规模和项目，不是魔法。

## 5. 训完如何评质量：没有一张统考卷

**没有**「MMLU 达到 xx 即可上线」的国际强制标准。行业习惯是 **可复现的多层评测**，不是一个万能分数。

```text
1. 训练健康     loss 是否正常（没训崩 ≠ 质量好）
2. 能力基准     公开题 + 内部私有集（防污染、防刷榜）
3. 人工         绝对分或 A vs B 成对比较
4. 安全         拒答、越狱、违法；过不了不能发版
5. 产品         延迟、成本、好评、A/B
```

公开基准只是事实标准（MMLU、GSM8K、HumanEval、IFEval、C-Eval、MT-Bench 等），必须固定解码参数。  
NLL/PPL 适合监控和同系列对比；字面 F1 适合小数据领域 SFT，开放聊天很弱。  
选择题高 ≠ 对话好用；数据污染会让公开分虚高。

你们已有最小闭环：独立 `test.jsonl` + 参考答案 + NLL/字面重合。往厂里习惯靠：评测脚本固定、题不与训练重复、开放生成加少量人工。

## 6. 速记卡片

1. `tokenize` 切片，`convert_tokens_to_ids` 查号，`encode` 两步合一，`__call__` 再打包 mask/张量。  
2. 中文被 BPE 拆碎是正常的；整字不在词表会拆字节，一般不是 UNK。  
3. Embedding 是内部查表层；`embedding(ids)` 按行取向量。  
4. `train()` 换挡；`backward` 阅卷；`step` 改作业。  
5. Dropout 训练随机蒙、推理全开；推理继续 `train()` 才会乱跳。  
6. 大厂与脚本同一公式；多的是数据、并行、容错和评测门禁。  
7. 质量评估是多维度流程，没有一张行业统考卷。
